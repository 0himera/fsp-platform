# Арена ФСП Дагестана

Рабочий MVP платформы Федерации спортивного программирования Республики Дагестан: аккаунт спортсмена, соревнования, заявки, командные составы, публикация результатов и объяснимый рейтинг.

Информационная часть представлена простым разделом с календарём, методикой и местами для новостей и документов; полноценная CMS в MVP не нужна.

## Запуск

```bash
docker compose up --build
```

Откройте [localhost:8080](http://localhost:8080). Демосидер создаёт 524 спортсмена и 19 соревнований: 13 с опубликованными протоколами и 6 с открытой регистрацией. Среди них отбор на 300 человек, связанный финал на 200, отдельный Кубок России на 200 и предстоящий старт с 200 заявками. Повторный запуск не дублирует записи и не перезаписывает изменённые профили. База хранится в Docker volume.

Демо-доступ:

| Роль | Почта | Пароль |
| --- | --- | --- |
| Организатор | `organizer@arena.local` | `change-me-for-local-demo` |
| Спортсмен | `athlete1@arena.local` | `demo-athlete-2026` |

Можно также зарегистрировать нового спортсмена через интерфейс. Первые 24 демонстрационных спортсмена доступны для входа по образцу `athlete1@arena.local`; ещё 500 профилей созданы для проверки больших сеток и намеренно не имеют рабочего пароля. Учётная запись организатора создаётся только из переменных окружения `SEED_ORGANIZER_EMAIL` и `SEED_ORGANIZER_PASSWORD`. Демонстрационные данные включаются через `DEMO_SEED=1`; настройки Compose предназначены для локального показа.

Для запуска Go вне контейнера сначала поднимите БД через `docker compose up -d db`, затем из `backend/` выполните:

```bash
DATABASE_URL='postgres://arena:arena@localhost:5432/arena?sslmode=disable' \
SEED_ORGANIZER_EMAIL='organizer@arena.local' \
SEED_ORGANIZER_PASSWORD='change-me-for-local-demo' \
DEMO_SEED=1 go run ./cmd/server
```

## Основной сценарий

1. Спортсмен регистрируется и открывает карточку соревнования.
2. Подаёт заявку. Она появляется в его профиле и в списке организатора.
3. Для командного зачёта организатор собирает команды из зарегистрированных спортсменов.
4. Организатор публикует итоговый протокол. Соревнование завершается, результаты отображаются в карточках и профилях, рейтинг рассчитывается заново.

Публикация протокола транзакционна. Повторная публикация заменяет текущие результаты и сохраняет предыдущую версию в `result_publications`. Изменение разряда доступно только организатору и записывается в `rank_changes`.

Организатор может создать связку «отбор → финал» и указать проходное место. Заявка в финал доступна только спортсмену, чей опубликованный результат отбора укладывается в этот порог. Протокол отбора остаётся в истории выступлений, но не приносит рейтинговых очков; финал оценивается по обычной формуле уровня соревнования.

## Рейтинг `arena-2`

Для спортсмена считаются четыре лучших подтверждённых результата и бонус за высший подтверждённый разряд:

```text
R = сумма 4 лучших P + Q(разряд) × A(дни после последнего результативного старта)
P = B(уровень) × C(место) × sqrt(min(N, 16) / 16) × (N − p) / (N − 1) × D(давность)
```

`N` — число финишировавших в конкретном зачёте, `p` — официальное место. При `N < 2` очков нет. Для командного зачёта `N` считается по командам; каждый спортсмен итогового состава получает одинаковое количество очков, без деления на размер команды. Результат этапа «отбор» даёт 0 очков и не активирует бонус разряда; финал считается как отдельный результат.

| Уровень `B` | Баллы | Место `C` | Коэффициент |
| --- | ---: | --- | ---: |
| Чемпионат / Кубок России | 1000 | 1-е | 1 |
| Другие всероссийские | 650 | 2-е | 0,7 |
| Межрегиональные | 400 | 3-е | 0,5 |
| Чемпионат / Кубок Дагестана | 250 | 4–5-е | 0,3 |
| Другие региональные | 120 | 6-е и далее | `0,15 × 6 / p` |

`D` плавно проходит через точки: 0 дней → 1; 365 → 0,7; 730 → 0,4; 1095 → 0. Бонус разряда использует `A = max(0, 1 − дни/730)`. Баллы за разряды: III — 10, II — 20, I — 45, КМС — 80, МС — 130, МСМК — 180, ЗМС — 250. Разряд остаётся в профиле после обнуления бонуса.

Рейтинг вычисляется при чтении из опубликованных протоколов; отдельный кеш и Redis для MVP не нужны. API возвращает коэффициенты и показывает, какие четыре результата вошли в сумму. Рейтинг является внутренним показателем федерации и не присваивает официальные разряды.

Спортсмены с одинаковой суммой очков делят место в таблице; для порядка отображения используется ФИО.

## Структура

```text
backend/
  cmd/server/          входная точка
  internal/auth/       аккаунты и сессии
  internal/athletes/   данные спортсмена и разряд
  internal/competitions/ соревнования, заявки, команды, протоколы
  internal/rating/     формула и расчёт
  internal/httpapi/    REST-маршруты
  internal/platform/   PostgreSQL и миграции
  migrations/          SQL-миграции
frontend/              статический интерфейс без сборщика
docker-compose.yml     приложение и PostgreSQL
```

Бэкенд — модульный монолит на Go с PostgreSQL. API — REST/JSON на `net/http`; доступ к БД через `pgx`. Пароли хранятся как Argon2id, сессии — в PostgreSQL, токен — в HttpOnly cookie.

Отдельная ветка `frontend` содержит прототип клиента на Next.js 16, React 19, Feature-Sliced Design и TanStack Query. Запускаемый MVP в `main` использует статический интерфейс из `frontend/`.

## Проверки

```bash
cd backend && go test ./...
node --check ../frontend/app.js
```

Fuzz-тесты проверяют ограничения баллов, монотонность по месту, размеру сетки и давности, правило четырёх лучших результатов и допустимость протоколов:

```bash
cd backend
go test -run '^$' -fuzz '^FuzzScoreInvariants$' -fuzztime=10s -parallel=2 ./internal/rating
go test -run '^$' -fuzz '^FuzzCalculateBestFour$' -fuzztime=10s -parallel=2 ./internal/rating
go test -run '^$' -fuzz '^FuzzValidateProtocol$' -fuzztime=10s -parallel=2 ./internal/competitions
```

Интеграционный тест создаёт временную схему PostgreSQL, проверяет 524 профиля, крупные протоколы, повторный сидинг, допуск в финал, заявки, публикацию, исправление результатов и рейтинг, затем удаляет схему:

```bash
docker compose up -d db
cd backend
TEST_DATABASE_URL='postgres://arena:arena@localhost:5432/arena?sslmode=disable' go test -run '^TestSeedAndMainFlow$' -v ./internal/demo
```
