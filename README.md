# Арена ФСП Дагестана

Рабочий MVP платформы Федерации спортивного программирования Республики Дагестан: аккаунт спортсмена, соревнования, заявки, командные составы, публикация результатов и объяснимый рейтинг.

Информационная часть представлена простым разделом с календарём, методикой и местами для новостей и документов; полноценная CMS в MVP не нужна.

## Запуск

```bash
docker compose up --build
```

Откройте основной интерфейс Next.js на [localhost:3000](http://localhost:3000). Статический фронтенд и Go API остаются доступны на [localhost:8080](http://localhost:8080) как рабочий референс поведения API. Демосидер создаёт 524 спортсмена и 19 соревнований: 13 с опубликованными протоколами и 6 с открытой регистрацией. Среди них отбор на 300 человек, связанный финал на 200, отдельный Кубок России на 200 и предстоящий старт с 200 заявками. Повторный запуск не дублирует записи и не перезаписывает изменённые профили. База хранится в Docker volume.

При регистрации спортсмен получает письмо для подтверждения адреса. Локально письма перехватывает Mailpit: [localhost:8025](http://localhost:8025). Они не уходят на реальные адреса. После подтверждения можно войти; на странице входа доступны повторная отправка письма и восстановление пароля. Если отправка письма не удалась, аккаунт остаётся созданным, а интерфейс предлагает запросить письмо повторно через минуту.

Демо-доступ:

| Роль | Почта | Пароль |
| --- | --- | --- |
| Организатор | `organizer@arena.local` | `change-me-for-local-demo` |
| Спортсмен | `athlete1@arena.local` | `demo-athlete-2026` |

Можно также зарегистрировать нового спортсмена через интерфейс. Первые 24 демонстрационных спортсмена доступны для входа по образцу `athlete1@arena.local`; ещё 500 профилей созданы для проверки больших сеток и намеренно не имеют рабочего пароля. Учётная запись организатора создаётся только из переменных окружения `SEED_ORGANIZER_EMAIL` и `SEED_ORGANIZER_PASSWORD`. Демонстрационные данные включаются через `DEMO_SEED=1`; настройки Compose предназначены для локального показа.

Для запуска Go вне контейнера сначала поднимите БД и почтовый ящик через `docker compose up -d db mailpit`, затем из `backend/` выполните:

```bash
DATABASE_URL='postgres://arena:arena@localhost:5432/arena?sslmode=disable' \
SEED_ORGANIZER_EMAIL='organizer@arena.local' \
SEED_ORGANIZER_PASSWORD='change-me-for-local-demo' \
DEMO_SEED=1 go run ./cmd/server
```

Для регистрации при таком запуске добавьте `SMTP_HOST=localhost SMTP_PORT=1025 SMTP_FROM='Арена ФСП РД <noreply@arena.local>' PUBLIC_BASE_URL=http://localhost:3000`. Без настроенного SMTP вход в существующие аккаунты работает, но регистрация и восстановление пароля недоступны. Для отправки реальных писем укажите SMTP-сервер, порт, адрес отправителя и при необходимости `SMTP_USERNAME`/`SMTP_PASSWORD`. Сервер поддерживает STARTTLS и TLS на порту 465; `PUBLIC_BASE_URL` должен совпадать с публичным адресом платформы. Локальный Mailpit нужен только для разработки и показа.

## Основной сценарий

1. Спортсмен регистрируется и открывает карточку соревнования.
2. Подаёт заявку. Она появляется в его профиле и в списке организатора.
3. Для командного зачёта организатор собирает команды из зарегистрированных спортсменов.
4. Организатор публикует итоговый протокол. Соревнование завершается, результаты отображаются в карточках и профилях, рейтинг рассчитывается заново.

Протокол доступен после указанного времени завершения. Если старт закончился раньше, организатор нажимает «Завершить досрочно» в карточке: система фиксирует фактическое время и закрывает заявки. Публикация протокола транзакционна. Повторная публикация заменяет текущие результаты и сохраняет предыдущую версию в `result_publications`. После публикации организатор может исправить название, место и описание через `PUT /api/competitions/{id}`; уровень, дисциплина, формат, даты и этап заблокированы, чтобы не менять уже рассчитанный рейтинг. Изменение разряда доступно только организатору и записывается в `rank_changes`.

API соревнований возвращает сохранённый `status`, вычисляемую по датам `phase` (`upcoming`, `current`, `awaiting_results`, `completed` или `draft`) и `registration_open`. Список поддерживает фильтр `?phase=...`. В данных выступления спортсмена также возвращается исходный `score_text` из протокола вместе с местом и рейтинговыми баллами.

Организатор может создать связку «отбор → финал» и указать проходное место. Заявка в финал доступна только спортсмену, чей опубликованный результат отбора укладывается в этот порог. Протокол отбора остаётся в истории выступлений, но не приносит рейтинговых очков; финал оценивается по обычной формуле уровня соревнования.

## Export API для сторонних площадок

Сторонние площадки проведения могут получить полный дамп соревнования (метаданные, список участников, команды и протокол результатов) через машинный эндпоинт без авторизации через cookie.

**Эндпоинт:**

```
GET /api/competitions/{id}/export
Authorization: Bearer <EXPORT_API_TOKEN>
```

**Пример (curl):**

```bash
curl -H "Authorization: Bearer a0915aba3191bc0399466376ddcb88fe5e7146867537eccfae8828d1cfcec072" \
     http://localhost:8080/api/competitions/1/export
```

**Схема ответа (`200 OK`):**

```json
{
  "competition": { /* объект Competition */ },
  "registrations": [
    {
      "athlete_id": 42,
      "full_name": "Иван Иванов",
      "organization": "ДГТУ",
      "city": "Махачкала",
      "created_at": "2026-09-01T10:00:00Z",
      "avatar_url": ""
    }
  ],
  "teams": [
    {
      "id": 1,
      "name": "Team Alpha",
      "captain_id": 42,
      "members": [ /* массив Registration */ ]
    }
  ],
  "results": [
    {
      "id": 1,
      "athlete_id": 42,
      "team_id": 0,
      "place": 1,
      "score_text": "1200 очков",
      "name": "Иван Иванов"
    }
  ]
}
```

Для индивидуального зачёта `team_id = 0`, для командного — `athlete_id = 0`. Поле `teams` будет пустым (`[]`) для индивидуальных соревнований.

**Конфигурация:** задайте переменную окружения `EXPORT_API_TOKEN`. Если переменная не задана, эндпоинт вернёт `503`. Для смены токена достаточно перезапустить сервер с новым значением — токены не хранятся в базе.

> **Демо-токен** (`.env.example`): `a0915aba3191bc0399466376ddcb88fe5e7146867537eccfae8828d1cfcec072` — смените перед выходом в продакшн.

## Дополнительные модули и возможности

1. **Интерактивный календарь соревнований (`/calendar`)**:
   - Месячная календарная сетка с понедельника по воскресенье.
   - Цветовая индикация фаз соревнований: предстоящие (синий), текущие (зелёный), ожидающие итогов (оранжевый), завершённые (серый).
   - Быстрый переход в карточку турнира по клику на событие в ячейке дня.
   - Навигация по месяцам.

2. **Специалисты: Тренеры, наставники и спортивные судьи (`/coaches`)**:
   - Роли `coach` (тренер/наставник) и `judge` (спортивный судья) доступны при регистрации.
   - Единая картотека специалистов с указанием организации, города и спортивной биографии.
   - Формирование судейской коллегии соревнований: организатор может назначать судей и указывать должность в коллегии (главный судья, секретарь и др.). Вкладка «Судейская коллегия» доступна в карточке каждого соревнования.

3. **Система уведомлений пользователей**:
   - Индикатор непрочитанных уведомлений (колокольчик с бейджем) в шапке сайта.
   - Polling каждые 60 секунд.
   - Автоматическая рассылка уведомлений участникам при публикации итогового протокола и начислении рейтинга.
   - Эндпоинты `GET /api/notifications`, `POST /api/notifications/{id}/read`, `POST /api/notifications/read-all`.

4. **История изменения разряда**:
   - Хранение всех фактов изменения квалификации в таблице `rank_changes`.
   - API `GET /api/athletes/{id}/rank-history`.
   - Наглядная хронологическая лента переходов разрядов в профиле спортсмена.

5. **Расширенные фильтры соревнований (`/events`)**:
   - Фильтрация по статусу (все / предстоящие / завершённые).
   - Фильтрация по спортивным дисциплинам.
   - Фильтрация по уровню соревнований (Чемпионат РФ, Межрегиональный, Чемпионат РД, Региональный и др.).
   - Полнотекстовый поиск по названию, городу и дисциплине.

6. **ИИ-помощник с лёгким RAG на `pgvector` и Google Gemini (`/api/ai/chat`)**:
   - Векторная база данных на базе расширения PostgreSQL `pgvector` (`vector(768)`).
   - Эмбеддинги регламентов и документов на базе модели `gemini-embedding-001`.
   - Интеллектуальные ответы на вопросы спортсменов о турнирах, датах, дедлайнах и формуле рейтинга через `gemini-3.8-flash`.
   - Плавающий интерактивный виджет в интерфейсе платформы с быстрыми подсказками.

## Рейтинг `arena-2`

Для спортсмена считаются четыре лучших подтверждённых результата и бонус за высший подтверждённый разряд:

```text
R = сумма 4 лучших P + Q(разряд) × A(дни после последнего результативного старта)
P = B(уровень) × C(место) × sqrt(min(N, 16) / 16) × (N − p) / (N − 1) × D(давность)
```

`N` — число финишировавших в конкретном зачёте, `p` — официальное место. При `N < 2` очков нет. Для командного зачёта `N` считается по командам; каждый спортсмен итогового состава получает одинаковое количество очков, без деления на размер команды. Результат этапа «отбор» даёт 0 очков и не активирует бонус разряда; финал считается как отдельный результат.

| Уровень `B` | Баллы | Место `C` | Коэффициент |
| --- | ---: | --- | ---: |
| Чемпионат / Кубок России | 1000 | 1-е | 1 |
| Другие всероссийские | 650 | 2-е | 0,7 |
| Межрегиональные | 400 | 3-е | 0,5 |
| Чемпионат / Кубок Дагестана | 250 | 4–5-е | 0,3 |
| Другие региональные | 120 | 6-е и далее | `0,15 × 6 / p` |

`D` плавно проходит через точки: 0 дней → 1; 365 → 0,7; 730 → 0,4; 1095 → 0. Бонус разряда использует `A = max(0, 1 − дни/730)`. Баллы за разряды: III — 10, II — 20, I — 45, КМС — 80, МС — 130, МСМК — 180, ЗМС — 250. Разряд остаётся в профиле после обнуления бонуса.

Рейтинг вычисляется при чтении из опубликованных протоколов; отдельный кеш и Redis для MVP не нужны. API возвращает коэффициенты и показывает, какие четыре результата вошли в сумму. Рейтинг является внутренним показателем федерации и не присваивает официальные разряды.

Спортсмены с одинаковой суммой очков делят место в таблице; для порядка отображения используется ФИО.

## Структура

```text
backend/
  cmd/server/          входная точка
  internal/auth/       аккаунты и сессии
  internal/athletes/   данные спортсмена и разряд
  internal/competitions/ соревнования, заявки, команды, протоколы
  internal/rating/     формула и расчёт
  internal/httpapi/    REST-маршруты
  internal/platform/   PostgreSQL и миграции
  migrations/          SQL-миграции
frontend/src/          основной интерфейс Next.js 16
frontend/app.js        статический референс запросов и поведения
frontend/public/       изображения основного интерфейса Next.js
docker-compose.yml     приложение и PostgreSQL
```

Бэкенд — модульный монолит на Go с PostgreSQL. API — REST/JSON на `net/http`; доступ к БД через `pgx`. Пароли хранятся как Argon2id, сессии — в PostgreSQL, токен — в HttpOnly cookie. Новые аккаунты не могут войти до подтверждения адреса. Ссылки подтверждения и сброса одноразовые, в базе хранится только их SHA-256; они действуют 24 часа и 15 минут соответственно. Повторная отправка ограничена интервалом в минуту на адрес. Сброс пароля завершает все старые сессии. Аккаунты, созданные до введения проверки почты, миграция помечает как подтверждённые, чтобы не лишать их доступа.

Next.js-клиент на React 19, Feature-Sliced Design и TanStack Query — основной интерфейс. Статический клиент в `frontend/` сохранён как референс запросов и поведения; оба клиента обращаются к одному Go API.

## Проверки

```bash
cd backend && go test ./...
node --check ../frontend/app.js
```

Fuzz-тесты проверяют ограничения баллов, монотонность по месту, размеру сетки и давности, правило четырёх лучших результатов и допустимость протоколов:

```bash
cd backend
go test -run '^$' -fuzz '^FuzzScoreInvariants$' -fuzztime=10s -parallel=2 ./internal/rating
go test -run '^$' -fuzz '^FuzzCalculateBestFour$' -fuzztime=10s -parallel=2 ./internal/rating
go test -run '^$' -fuzz '^FuzzValidateProtocol$' -fuzztime=10s -parallel=2 ./internal/competitions
```

Интеграционный тест создаёт временную схему PostgreSQL, проверяет 524 профиля, крупные протоколы, повторный сидинг, допуск в финал, заявки, публикацию, исправление результатов и рейтинг, затем удаляет схему:

```bash
docker compose up -d db
cd backend
TEST_DATABASE_URL='postgres://arena:arena@localhost:5432/arena?sslmode=disable' go test -run '^TestSeedAndMainFlow$' -v ./internal/demo
```

Отдельный PostgreSQL-тест проверяет регистрацию с неподтверждённым адресом, одноразовое подтверждение, вход, сброс пароля и отзыв старых сессий:

```bash
TEST_DATABASE_URL='postgres://arena:arena@localhost:5432/arena?sslmode=disable' go test -run '^TestEmailAccountFlow$' -v ./internal/auth
```

Сбой отправки подтверждения и последующую повторную отправку проверяет `TestRegistrationWhenMailFails` в `internal/httpapi` с тем же `TEST_DATABASE_URL`.
